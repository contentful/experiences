## Target APIs and ordinary flows

### Initial content and exact submission

Use ordinary Node fetch for SSR and ordinary Web fetch for CSR/local navigation/
actions, with SDK-owned construction once. Only actual hybrid transfers produce
Node handoff results. Preserve existing fetch setup, payload-fetch/resolve splitting,
source maps, profile adoption, consent/interception/validation and lifetime guards.
Ordinary fetch remains plan-returning; do not box/unbox it through handoff results
or introduce a shared mode orchestrator. See [Runtime XDA contract](../packages/runtime/README.md#xda-preflight-and-profile-finalization).

### Existing producer and sender extensions

Retain only the actual server Node producer and optional explicit browser consumer.
Remove Node aggregate commit, Web producer, handoff-as-content reuse branches and
their helpers, standalone XPAPI preparation, separate supplied-data producers and
public state-only hydration. Necessary state application remains internal to the
existing complete consumer operation. The target Node declaration is:

```ts
fetchExperienceForHandoff(
  options: FetchExperienceOptions,
  resolveOptions: FetchResolveOptions,
  descriptor: { readonly routeKey: string }
): Promise<FetchExperienceForHandoffResult>;
// Full handoff plus optional plan/error; actual server-to-browser transfer only.
```

Keep the existing declared option/result types; no new API family, mode flags,
capture store/hook, root DSL or resource framework is specified. Incoming replay
uses the existing consent, queue and owner-lifetime mechanics.

### CSR ownership, refresh and consent

Phase 6 corrects existing Web/hybrid browser loading and current optional React consumption, including basic consent/lifecycle behavior. Phase 7 ports managed source/presentation loading and navigation coordination into React. CSR/local navigation uses ordinary Web fetch. Only actual hybrid transfers retain Node producer → optional explicitly supplied browser consumer. Reuse compatible pinned root/controller options and adapt XDA inputs in the owning loader; no separate root event-input DSL or cycle protocol is required. If retained, `beforeInitialPage` remains optional for standalone purposes, never a content gate; matching replay supersedes it and late completion cannot emit a competing page. Queue/refusal/failure outcomes remain truthful and never withhold a selected plan.

Ordinary content Retry refetches the same ID through ordinary fetch without events,
builders, event hooks, publication, admission or replay. Refresh creates no new
visitor intent; accepted incoming replay delivery retry remains queue-owned.
Initial URL identify pairs with the initial page; standalone Identify and CUSTOM
TRACK are fresh nonpage inputs to ordinary fetch, and navigation still carries
page intent. Current optional React/hybrid consumption observes SDK consent and
reinvokes the complete operation with a stable `isCurrent` guard; no extra page,
refetch or CSR capture is added. Preserve that implicit page exception in future
managed loading/navigation without direct emission as an initial prerequisite or an
explicit retry scheduler. Later reference comparison IDs use ordinary event-free
fetch with no SDK cross-fetch guarantee.

Preserve the pinned Optimization API mechanics and its product exception: the page emitter implicitly retries page on consent changes. Do not add an explicit consent retry scheduler, callback, state machine or content refetch. Other blocked events are dropped; allowlisted events are admitted rather than classified as blocked. Prepared replay uses the CURRENT browser consent gate for the whole batch, existing browser-consent restamping, and whole-batch refusal with gated fallback only for page-bearing intent. An integration's refused handoff is an integration outcome, not an SDK defect or a reason to bypass consent. Runtime consent stamping, final validation/interception, queues, reset/stale/lifetime guards and privacy boundaries remain owned by the SDK.

### Next request family and handoff

Port pinned request/runtime/root/provider/Experience/tracker ownership with memoization and optional prefetch for plan reuse. SDK integration officially supports one Experience fetch per page without code enforcement; the reference loops above are only for rendering-scenario comparison, not a supported product pattern. Add no mandatory descendant inventory, chaining controller, transaction guarantee or all-content barrier.

The actual hybrid descriptor content fetch produces the full Node result reused
by presentation/root even without optional prefetch. Optional preloading is separate;
do not return to XPAPI preparation or infer a batch from descendant inventory.
Capture applicable state and continuation fallback at supported boundaries. Preserve trusted context forwarding, middleware versus render/response boundaries, safe serialization, private credentials/resolvers, cache policy and response-cookie rules. Optional plans use the framework envelope, never request headers or an external continuation store.

Retain profileless internal state application and scope/cache validation within the full aggregate's complete operation. Remove standalone XPAPI preparation and supplied-data producers. Content rendering never waits for replay admission or HTTP completion.
